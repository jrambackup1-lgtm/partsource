## Question

Can a local, research-only PartSource instrument turn imperfect fastener clues into an explicit blocked state or safe review packet without false unique selection, stale actions, hidden defaults, private-field leakage, or supplier handoff?

## Decision context

## Bounded scope

- Local/internal research instrument only.
- One positive candidate profile: metric, coarse-thread, standard-profile, internal-hex socket-head cap screws.
- External-hex and pan-head forms are boundary/negative controls only.
- Supplied facts and notation remain immutable.
- Parsed/normalized facts stay separate and carry origin and rule version.
- Outputs are typed block reasons or synthetic candidate packets.
- No unique engineering selection.
- No `verified`, approved, equivalent, suitable, BOM-ready, orderable, stock, price, or availability claim.
- No alternate-supplier URL.
- No public data mutation, deployment, outreach, quote, cart, or order.
- Frozen benchmark v1 remains unchanged and forensic-only.

## Research tasks

- [ ] Encode the candidate profile and neighboring-form exclusions as explicitly non-authoritative synthetic fixtures.
- [ ] Create one shared constraint-and-release ledger for parser output, UI state, packet output, and tests.
- [ ] Create one blocked-first handoff compiler that returns either a typed block reason or an immutable synthetic packet.

## Acceptance tests

- [ ] Zero false-unique identity or selection after exact-identifier collisions and critical-field deletion.
- [ ] Wrong family, unit, thread, release, lifecycle, and conflict mutations change the result or force abstention.
- [ ] Zero BOM, copy, export, or supplier actions in broad, partial, conflict, unsupported, unavailable, stale, corrected, superseded, withdrawn, and no-release states.
- [ ] Zero stale prior actions while replacement requests load or fail.
- [ ] Zero private source fields outside the strict packet/DTO allowlist.
- [ ] Old snapshots remain byte-stable while correction or withdrawal blocks new handoff.
- [ ] Every blocked fixture names one precise next review action.
- [ ] Browser matrix runs against the intended build/base identity with clean console output except deliberate failure fixtures.

## Stop / rethink

Choose **C — rethink** if usefulness requires false unique output, hidden defaults, mutable released truth, unreleased supplier actions, broad privileged exposure, or a packet that gives no better next review action than preserving the original clue.

## Result — 2026-08-10

**FAIL — C — rethink.**

The initial fixture matrix passed 19/19 and the real-browser matrix passed its intended 16 blocked fixtures. An independent adversarial review then found trust-boundary defects. A main-session regression suite reproduced all of them: **0/11 passed; 11/11 failed**.

Controlling evidence: `research/proxy-poc-ticket25-results-2026-08-10.md`.

Blocking defects:

- manifest digests are not bound to immutable content;
- compound clue conflicts can resolve last-wins;
- duplicate manifest and configuration identities can select the first row;
- non-enumerable private fields and hostile accessors bypass the schema/error boundary;
- unknown lifecycle values are not globally rejected;
- correction/rollback fixtures mutate state instead of proving append-only history;
- the ledger does not carry all required fact states in one structure;
- next review actions are not field-specific.

No research-task or acceptance-test checkbox is marked complete because the controlling adversarial gate failed.

## Fundamental rethink resolution

This ticket is closed as a negative research result, not passed.

The failures split across three layers:

- architecture: trust root, identity cardinality, whole-release validity, immutable correction history, and one action-controlling fact state;
- data/domain: wrong entities, lossy projection, absent required-field profiles, unresolved mapping authority, and no qualified release approval;
- POC implementation: last-wins parsing, schema/accessor handling, empty normalized identity, and imprecise review actions.

Repairing the POC would not repair the missing buyer, authority, or data truth.

Automatic safe handoff is rejected as the active product direction. A human-owned raw-preserving issue list remains only a demand hypothesis.
