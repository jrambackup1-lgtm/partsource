# Critique — 007 engineering workspace directions

**Date:** 2026-08-09

## What works

- The blocker and next action dominate the queue composition.
- The original clue stays visible beside interpretation.
- Technical facts appear once instead of repeating across cards and banners.
- Queue, ledger, and resolver test behavioral differences, not cosmetic themes.
- The visual language is restrained and reads as an engineering work surface.

## Problems

- The fixed prototype switcher can overlap the right rail on short desktop viewports.
- Queue counts can become dashboard theatre unless they correspond to real unresolved lines.
- The ledger can become bureaucratic for clean exact-ID cases.
- The resolver can become a slow wizard if question order is fixed or unreviewed.
- Green must not imply engineering approval; it is safe only for a defined released state.
- Long identifiers, 320 px reflow, keyboard order, and screen-reader behavior are untested.
- Fixture release and mapping language must never be mistaken for current catalog claims.

## Follow-up test

Use recent redacted engineer cases. Compare the current app with the hybrid queue/ledger/resolver flow. Measure time, wrong turns, noticed unknowns, accepted substitutions, review effort, and reuse of the frozen packet.
